## 내 사이트가 준비할 부분은 무엇인가요?

설치 안내에서 나오는 **호스트 앱**은 메미보드를 붙일 웹사이트를 뜻합니다. 이번 강의에서는 memi.dev가 호스트입니다.

메미보드가 게시판의 화면과 기능을 제공하고, 내 사이트에서는 사용할 주소와 레이아웃, Firebase 연결 등을 준비합니다.

| 구성 | 담당하는 역할 |
|---|---|
| 내 사이트 | 페이지 주소, 메뉴, 레이아웃, Firebase 연결 |
| 메미보드 | 게시글·댓글·첨부 파일 등 게시판 화면과 기능 |
| Firebase | 로그인 처리, 데이터와 파일 저장, 보안 규칙에 따른 접근 제어 |

예를 들어 메뉴에 게시판 링크를 추가하고 `/board`라는 주소를 만드는 작업은 내 사이트에서 합니다. 그 페이지 안에 메미보드의 컴포넌트를 연결해 게시판을 표시하는 방식입니다.

## 개발 환경을 확인합니다

먼저 **로컬에서 실행할 수 있는 Nuxt 4 프로젝트**가 필요합니다. 기존 사이트에 적용한다면 그 프로젝트를 사용하면 됩니다.

메미보드는 다음 구성을 기준으로 동작합니다.

- **Nuxt 4 이상**: 사이트와 페이지를 구성합니다.
- **Nuxt UI 4 이상**: 버튼, 입력창 등 화면 요소를 제공합니다.
- **Firebase**: 로그인과 데이터·파일 저장에 사용합니다.
- **Nuxt VueFire**: Nuxt에서 Firebase를 연결하고 사용할 수 있도록 돕습니다.

Node.js와 pnpm도 사용할 수 있어야 합니다. 터미널에서 다음 명령으로 설치 여부와 버전을 확인할 수 있습니다.

```bash
node --version
pnpm --version
```

Node.js는 사용하는 Nuxt 버전이 요구하는 버전에 맞춰 준비합니다. 프로젝트의 `package.json`에서는 Nuxt와 Nuxt UI 등 기존 의존성도 확인해두세요.

이미 사이트가 있다면 메미보드를 추가하기 전에 현재 상태로 정상 실행되는지 확인합니다. 그래야 이후 문제가 생겼을 때 기존 프로젝트의 문제인지, 연결 과정의 문제인지 구분하기 쉽습니다.

## Firebase 프로젝트를 준비합니다

**게시판에서 사용할 Firebase 프로젝트 하나를 정합니다.** 기존 사이트에서 Firebase를 사용하고 있다면 같은 프로젝트를 사용할 수 있습니다. 새로 연습하는 경우에는 연습용 프로젝트를 준비해도 됩니다.

게시판의 기본 기능에 사용하는 서비스는 다음 세 가지입니다.

| 서비스 | 게시판에서 사용하는 곳 |
|---|---|
| Authentication | Google 로그인 등 사용자 인증 |
| Cloud Firestore | 게시글, 댓글, 게시판 설정 등 데이터 저장 |
| Cloud Storage | 이미지와 첨부 파일 저장 |

Firebase 콘솔에서 선택한 프로젝트에 웹 앱이 등록되어 있는지 확인하고, 해당 웹 앱의 Firebase 설정 정보를 준비합니다. 다음 편에서 이 정보를 사이트의 VueFire 설정에 연결합니다.

기존 프로젝트를 사용한다면 Authentication, Firestore, Storage의 현재 설정도 확인해두세요. 로그인 제공업체와 허용 도메인, Storage의 사용 조건·결제 요건은 프로젝트 상태에 따라 추가 설정이 필요할 수 있습니다.

이때 필요한 것은 **Firebase 웹 앱 설정 정보**입니다. Firebase Admin용 서비스 계정 키를 브라우저에서 사용하는 설정에 넣으면 안 됩니다.

보안 규칙과 인덱스 적용도 이후 연결 과정에 포함됩니다. 패키지를 설치하는 것만으로 Firebase의 접근 권한까지 자동으로 설정되지는 않습니다.

- **게시판 이름**: 자유게시판, 공지사항, 개발 노트 등
