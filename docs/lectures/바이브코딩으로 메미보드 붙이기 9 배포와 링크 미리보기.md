# 배포하고 링크 미리보기 확인하기

지난 글에서는 AI Logic과 App Check를 연결했습니다. 이번에는 **운영 사이트에 배포하고, 카카오톡과 슬랙에서 링크 미리보기**가 잘 나오는지 확인하겠습니다.

로컬에서 잘 되던 기능도 운영 주소에서는 막히는 경우가 많습니다. 대부분 **주소(도메인)를 등록하지 않아서** 생깁니다.

## 배포 방식을 정합니다

메미보드는 서버 렌더링(SSR)을 사용하므로 **Node 서버가 동작하는 곳**에 배포합니다. memi.dev는 Firebase App Hosting을 사용합니다. GitHub 저장소를 연결해 두면 `main`에 푸시할 때마다 자동으로 배포됩니다.

> 이 Nuxt 프로젝트를 Firebase App Hosting으로 배포하려고 해. 필요한 `apphosting.yaml`과 환경 변수 설정을 정리해줘.

정적 파일로만 내보내면(`nuxt generate`) 글 페이지의 링크 미리보기가 비게 됩니다. 기존 사이트가 정적 호스팅이라면 이 부분부터 AI와 상의합니다.

## 운영 주소를 등록합니다

배포 전에 운영 주소를 **세 곳**에 등록합니다.

**Firebase Authentication → 승인된 도메인**: 빠지면 로그인 창이 열리지 않습니다.

**reCAPTCHA 키의 도메인**: 빠지면 App Check 토큰을 받지 못해 AI 기능이 실패합니다.

**`seo.siteUrl`**: 링크 미리보기의 주소 기준입니다. 끝에 `/`를 붙이지 않습니다.

```ts
memiBoard: {
  seo: {
    siteName: '내 사이트',
    siteUrl: 'https://example.com',
    defaultOgImage: '/images/og-default.jpg',
    basePath: '/board',
  },
},
```

`defaultOgImage`는 글에 이미지가 없을 때 미리보기에 쓰는 기본 이미지입니다.

로컬에서 쓰던 **App Check 디버그 토큰은 운영에서 쓰지 않습니다.** 플러그인이 운영 환경에서는 디버그 토큰을 켜지 않는지 확인합니다.

## 보안 규칙은 따로 배포합니다

사이트를 배포해도 Firebase 보안 규칙과 인덱스는 올라가지 않습니다. 규칙 파일을 고쳤다면 사이트 배포와 별도로 배포합니다.

```bash
firebase deploy --only firestore:rules,storage,firestore:indexes
```

## 링크 미리보기를 확인합니다

미리보기는 4편에서 목록·상세 페이지에 넣은 SEO 한 줄이 만듭니다. 서버가 보내는 HTML에 제목과 이미지가 들어 있어야 카카오톡과 슬랙이 읽을 수 있습니다.

배포한 주소로 확인합니다.

```bash
curl -sL 'https://example.com/board/free/글-주소' | grep og:title
```

`og:title`과 `og:image`가 나오면 성공입니다. 브라우저의 개발자 도구 Elements 탭은 화면을 그린 뒤의 모습이라 정확하지 않습니다. **페이지 소스 보기**로 확인합니다.

그다음 카카오톡이나 슬랙에 글 주소를 붙여 봅니다. 로컬 주소(`localhost`)는 외부에서 읽을 수 없으므로 반드시 운영 주소로 확인합니다.

미리보기가 비어 있다면 이렇게 확인합니다.

- 목록·상세 페이지에 `ssr: false`가 걸려 있지 않은지 (3편)
- 숨김 보드의 글이 아닌지. 숨김 보드는 미리보기를 만들지 않습니다.
- 카카오톡은 미리보기를 저장해 두므로, 고친 뒤에도 예전 모습이 보일 수 있습니다.
