# 운영하고 업데이트하기

지난 글에서는 운영 사이트에 배포하고 링크 미리보기를 확인했습니다. 마지막 편에서는 **게시판을 운영하며 필요한 기능과 메미보드를 업데이트하는 방법**을 살펴보겠습니다.

## 사용자 페이지를 붙입니다

글쓴이를 눌렀을 때 볼 프로필과 사용자 목록이 있으면 커뮤니티 느낌이 납니다. 이것도 내 사이트가 페이지를 만들고 컴포넌트를 놓습니다.

**사용자 목록** `/board-users`: `MemiBoardUsers`. 이름과 역할만 보이고 이메일은 보이지 않습니다.

**공개 프로필** `/board-user/[uid]`: `MemiBoardProfile`. 그 사람이 쓴 글과 댓글이 보입니다.

**내 프로필 수정** `/board-account`: 로그인한 사람만 들어오는 페이지입니다.

> memi-board의 `docs/host-integration.md` 6번을 참고해서 사용자 목록, 공개 프로필, 내 프로필 수정 페이지를 만들어줘. 내 프로필 페이지는 로그인한 사람만 들어오게 해줘.

## 신고를 처리합니다

로그인한 사용자는 다른 사람의 글과 댓글을 신고할 수 있습니다. 신고를 처리할 관리 페이지를 하나 만듭니다.

> `MemiBoardReportList`로 `/admin/reports` 신고 관리 페이지를 만들어줘. 관리자만 들어오게 해줘.

신고 목록은 처리 전과 처리한 기록으로 나뉩니다. 처리할 때는 **공개 사유**를 적어야 하고, 신고한 사람은 신고 버튼을 다시 눌러 결과를 볼 수 있습니다. 댓글 신고는 처리하면서 그 댓글을 가릴 수도 있습니다.

신고 기능도 보안 규칙에 들어 있습니다. 규칙을 최신으로 배포하지 않으면 신고가 저장되지 않습니다.

## 남은 파일을 정리합니다

글을 지워도 이미지 파일이나 댓글이 남는 경우가 있습니다. 보드 설정 화면의 **고아 파일·문서 정리**에서 **고아 항목 조회**를 누르면 부모 글이 없는 파일, 댓글, 좋아요를 찾아줍니다.

목록을 확인하고 하나씩 또는 한꺼번에 지웁니다. 최근 24시간 안에 올라온 파일과 아직 쓰이는 파일은 지우지 않습니다. 전체 데이터를 읽으므로 **사용자가 적은 시간에** 실행하는 것이 좋습니다.

## 메미보드를 업데이트합니다

메미보드는 계속 기능이 추가되고 고쳐집니다. 업데이트는 패키지를 올리는 것으로 시작합니다.

```bash
pnpm add memi-board@latest
```

그런데 **패키지만 올리면 끝나지 않는 경우**가 있습니다. 새 기능이 보안 규칙이나 인덱스 변경을 요구할 때입니다. 그래서 업데이트할 때는 AI에게 변경 기록을 함께 읽게 합니다.

> memi-board를 최신 버전으로 올려줘. 지금 버전부터 새 버전까지 CHANGELOG의 Host app steps를 읽고, 이 사이트에서 해야 할 일을 정리해줘.

CHANGELOG의 각 버전에는 **Host app steps**가 있어서, 그 버전에서 내 사이트가 할 일이 적혀 있습니다. 대부분 아래 중 하나입니다.

- 보안 규칙 예제를 다시 합치고 배포
- 인덱스 추가
- 설정 옵션 추가

할 일이 없으면 패키지만 올리고 배포하면 됩니다. 규칙 변경이 있으면 **사이트 배포 전에 규칙을 먼저 배포**합니다. 새 코드가 새 규칙을 기대하기 때문입니다.

## 강의를 마치며

열 편에 걸쳐 memi.dev에 메미보드를 붙이는 과정을 따라왔습니다.

1. 패키지를 설치하고 Firebase를 연결했습니다.
2. 페이지를 만들고 보안 규칙을 배포했습니다.
3. 첫 관리자를 정하고 보드를 만들어 글을 썼습니다.
4. 역할, 번역, AI 기능을 더했습니다.
5. 배포하고 운영하는 방법을 살펴봤습니다.

모든 단계에서 AI에게 **먼저 계획을 받고, 결과는 직접 확인하는 방식**으로 진행했습니다. 메미보드의 문서는 AI가 읽기 좋게 정리되어 있으니, 막히는 부분이 있으면 문서와 함께 물어보세요.
