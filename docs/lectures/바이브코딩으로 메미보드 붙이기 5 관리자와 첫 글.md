# 첫 관리자를 정하고 첫 글 쓰기

지난 글에서는 게시판 페이지를 만들고 보안 규칙과 인덱스를 배포했습니다. 이번에는 **첫 관리자를 지정하고, 게시판을 만든 뒤 실제로 글을 써보겠습니다.**

게시판은 관리자만 만들 수 있습니다. 그런데 처음에는 관리자가 아무도 없습니다. 그래서 **첫 관리자만은 Firebase 콘솔에서 직접 지정**하고, 그다음부터는 화면에서 관리합니다.

## 로그인과 관리 페이지를 만듭니다

AI에게 남은 페이지를 요청합니다.

> memi-board의 `docs/host-integration.md` 6번을 읽고, 로그인 페이지와 `/admin/board-settings`, `/admin/board-users-settings` 관리 페이지를 만들어줘. 관리 페이지에는 owner와 admin만 들어갈 수 있는 미들웨어를 붙여줘.

만들어질 페이지는 다음과 같습니다.

**로그인**: `MemiBoardSignIn`을 놓은 페이지

**게시판 설정**: `/admin/board-settings`에 `MemiBoardSettings`

**사용자 권한**: `/admin/board-users-settings`에 `MemiBoardUsersSettings`

관리 페이지를 막는 미들웨어는 내 사이트가 만듭니다. memi.dev에서는 이렇게 사용자 문서의 역할을 확인합니다.

```ts
export default defineNuxtRouteMiddleware(async () => {
  if (import.meta.server) return
  const user = await getCurrentUser()
  if (!user) return navigateTo('/auth/login')
  const snap = await getDoc(doc(useFirestore(), 'memiBoardUsers', user.uid))
  if (!['owner', 'admin'].includes(snap.data()?.role)) return navigateTo('/')
})
```

메뉴를 숨기거나 미들웨어로 막는 것은 **화면을 정리하는 일**입니다. 실제로 데이터를 지키는 것은 지난 편에 배포한 보안 규칙입니다.

## 로그인하고 첫 관리자를 지정합니다

먼저 Firebase 콘솔의 Authentication에서 **Google 로그인을 켜고**, 승인된 도메인에 사이트 주소가 있는지 확인합니다. 로컬에서는 `localhost`가 기본으로 들어 있습니다.

1. 사이트의 로그인 페이지에서 Google로 로그인합니다.
2. Firebase 콘솔 → Firestore에서 `memiBoardUsers` 컬렉션을 엽니다. 방금 로그인한 계정의 문서가 생겨 있습니다.
3. 그 문서의 `role` 값을 문자열 `owner`로 바꿉니다.
4. 사이트를 새로고침하거나 다시 로그인합니다.

내 계정이 어느 문서인지 모르겠다면 Authentication → 사용자 목록에서 UID를 확인하면 됩니다.

이 단계는 **AI에게 맡기지 않고 직접** 합니다. 관리자 UID를 코드에 넣거나, 규칙을 우회하는 코드를 만들자고 하면 거절해주세요. 첫 관리자는 콘솔에서 한 번만 지정하면 됩니다.

## 게시판을 만듭니다

`/admin/board-settings`에 들어가면 보드 설정 화면이 열립니다. 메미보드에서는 게시판을 **보드**라고 부릅니다.

새 보드 이름 칸에 `free`를 입력하고 추가합니다. **처음 입력한 이름이 보드 주소가 되므로** 영문 소문자로 짧게 넣는 것이 좋습니다. 입력란 아래에 `주소: /board/free`처럼 미리 보여줍니다.

추가한 뒤에는 보드 설정에서 화면에 보일 이름을 자유게시판으로 바꾸고, 읽기·쓰기 권한을 지난 편에 정한 대로 맞춥니다. 기본값은 누구나 읽고 일반 사용자 이상이 쓰는 설정입니다.

## 첫 글을 씁니다

이제 `/board/free`로 가면 빈 목록과 글쓰기 버튼이 보입니다. 글쓰기를 눌러 제목과 본문을 쓰고 저장합니다.

저장하면 새 글 페이지로 이동하고, 주소는 `/board/free/글-제목` 형태가 됩니다. 목록으로 돌아가 글이 보이면 성공입니다.

잘 안 될 때는 이렇게 확인합니다.

- `permission-denied`: 보안 규칙이 배포되지 않았거나, 역할이 반영되지 않았습니다. 다시 로그인해봅니다.
- 이미지 업로드 실패: Storage 규칙과 버킷 설정을 확인합니다.
- 관리 페이지에서 쫓겨남: `role` 값에 오타나 공백이 없는지 확인합니다.

오류 메시지는 그대로 AI에게 붙여 넣고, 이번에 만든 페이지와 미들웨어를 기준으로 원인을 찾아달라고 요청합니다.
